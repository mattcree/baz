# Contributing to baz

Thanks for considering it. Two documents are required reading:

- [`docs/ENGINEERING.md`](docs/ENGINEERING.md) — the quality bar and how CI enforces it
- [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md) — getting a build environment

## Ground rules

- **Small, single-purpose PRs.** Commit messages explain *why*.
- **Green CI is necessary, not sufficient** — review is real, and reviewers
  will ask about anything they can't defend themselves.
- **New dependencies are decisions**, not reflexes; expect to justify them
  (license must clear `deny.toml`).
- **Architecture-level choices get an ADR** in `docs/adr/` before or with the PR.
- **AI assistance is welcome and disclosed** (co-author trailer). You own what
  you submit: be ready to explain every line. See the trust policy in
  `docs/ENGINEERING.md`.
- **Sign-off**: use `git commit -s` (Developer Certificate of Origin). No CLA.

## Where to start

`docs/NEXT-STEPS.md` tracks the current phase. Issues tagged `good-first` will
exist once there is a public tracker.
