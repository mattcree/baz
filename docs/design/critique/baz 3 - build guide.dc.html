baz — Build Guide

Scope, order, iced-specific notes, and the open questions. Rust + iced 0.13; constraints are real: no clipped images, no animation runtime, 4-sided borders only, no icon set, no accessibility tree, 100k-track virtualization, ~200ms cold start.

Deferrals are designed, not discarded — each has a mock on the board and slots into existing machinery (Crate = a lens word; overview = a zoom stop; crates = a group key; mixtapes = the stack's save path).

BUILD ORDER

  1. History ledger first. Append-only file, written from the first beta build even with zero UI — history cannot be backfilled, and the PLAYED key, the card, and the pull all feed on it.
  2. Room tokens + elevation primitives (the four surface levels, hairline-edge helper, state overlays).
  3. Wall: virtualized grid, shelf headers, selection/playing states, halo.
  4. Type-to-filter + Enter-plays-first; modifier-layer shortcuts.
  5. Needle: segmented groove, wall label, transport keys, hover-reveal transport on the playing cover.
  6. Inspector: track list, sides, inline tag edit, the card.
  7. Stack: shift+click, numeral chips, popover, ephemerality.
  8. Group keys + index rail (rail derives from the active key).
  9. Shuffle-what-you-see + the pull.
  10. Marquee lens + idle behavior.
  11. First-run/import wall; folder watching.
  12. Rooms 2–4 + follow-system switching (build on tokens from step 2 — cheap if step 2 was honest).

Steps 3–5 are the product: wall → click → sound. Everything after is additive; nothing before it ships without them.

ICED NOTES

  • Hairline edges: 4-sided borders can't draw one edge — stack a 1px-tall container (or a custom quad) along the lit side instead.
  • Halo: ring = 2px offset quad behind the art; bloom (Closing Time only) = layered translucent quads or a small custom widget. Test for banding at 6–10% ivory on cheap panels.
  • Marquee scrim: one quad with per-vertex alpha; no gradient API needed.
  • Zoom/density: 3–4 discrete stops, no tweening — a hard cut between grid metrics is shelf-like, not broken.
  • Glyph inventory (total): play, pause, prev, next — four hand-rasterised polygons, shown only over the playing cover on hover. Everything else is type.
  • Groove segments: plain rects from track durations; side break = wider gap. Click-to-jump = hit-test on segment index.
  • Rotated text (Crate lens, deferred) means rasterising glyph runs — the reason it's deferred; prove it cheap before committing.
  • Keyboard: global shortcuts don't need the focus tree. But no AT tree means screen-reader support is zero — see open questions.
  • Cold start: resume = persist wall scroll offset + paused track/position on every change, restore before first paint; thumbnail cache keyed by file mtime so the wall paints from cache, art decodes lazily.

OPEN QUESTIONS

  • Accessibility. No AT tree and no keyboard focus is a product risk beyond visual design, and this audience lives on keyboards. The type-to-filter + modifier-layer scheme covers operation; screen-reader access has no current answer. Decide the stance before 1.0, not after.
  • Hover-reveal transport with no animation — crisp or broken? Usability-test the hard cut (5a).
  • Mid-value sleeve melt on Stone/Plaster — validate against real libraries; remedy is nudging room L (.33 / .76), never borders on art (8b).
  • Art-derived accent hue — if revisited: hue clamped to the room's arc, amber/oxblood fallback below a chroma threshold; ship only if users notice unprompted (the board's hue tweak demos the failure).
  • “No search box” onboarding — first-run hint for users who look for a field? One quiet line, once, or nothing.

DEFINITION OF DONE

v1 is done when the friction budget holds on a 20,000-album library on mid hardware: launch→resume <200ms · click→sound <100ms perceived · keystroke→filter next frame · import with zero dialogs · tag fix without pausing playback — and the wall at rest is 100% collection in all four rooms.
