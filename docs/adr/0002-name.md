# ADR-0002: Name — "baz"

**Status**: accepted (2026-08-07)

## Context

The name follows the metasyntactic sequence foo, bar, baz — an homage to foobar2000, which baz is inspired by. Risk: "baz" is an extremely common placeholder identifier; collisions had to be checked before committing.

> **Amendment, 2026-08-10 — the homage is not a claim of succession.** This
> line originally read *"whose spiritual successor baz aims to be"*, and the
> owner corrected it while the README was being written for the public beta:
> *"make sure we say inspired by foobar but not a spiritual successor as they
> are different."* The distinction is real rather than modest. What baz took
> from foobar2000 is a posture — instant, correct, no commercial agenda, your
> files as the point rather than an import step. Everything downstream of that
> is baz's own and mostly disagrees with it: a different platform, a different
> decade, and an interface that is the collection rather than a configuration
> surface. The name stays an homage; the inheritance is not claimed. Every
> user-facing statement of it was corrected in the same commit — `README.md`
> and `docs/VISION.md`.

## Availability check (2026-08-07)

| Registry | Result |
|---|---|
| crates.io `baz` | **free** ("crate does not exist") |
| crates.io `baz-core` | **free** |
| crates.io `baz-player` | **free** |
| crates.io `bazplayer` | **free** |
| Homebrew formula `baz` | **free** (404) |
| Homebrew cask `baz` | **free** (404) |
| winget `manifests/b/Baz*` | **free** (0 results in microsoft/winget-pkgs) |
| Flathub | no collision; nearest is "Bazaar" (a Flatpak app store GUI) — different name, different domain |
| GitHub | thousands of placeholder repos named "baz" exist, but none is a music player of note (verified in earlier research); `<owner>/baz` is available per-account |

Also checked in earlier research (`docs/research/`): no existing music player named "baz" or "baz2000" anywhere; the unrelated BZR Player is the closest phonetic neighbor.

## Decision

- Project and binary name: **`baz`** (lowercase).
- Crate names: `baz` (app), `baz-core` (engine). **crates.io reservation: skipped by owner decision (2026-08-07)** — baz is an application distributed as binaries/packages, not a library consumed via crates.io; squatting of the crate name would not block the project. Revisit only if `baz-core` is ever published as a standalone library.
- Flatpak app ID: reverse-DNS, decided when the repo home is fixed (e.g. `io.github.<owner>.baz`).
  **Settled (2026-08-07, packaging work): `io.github.mattcree.baz`**, from the
  repo home `github.com/mattcree/baz`. Flatpak requires an application id it
  can attribute to something the author demonstrably controls, and it requires
  the desktop entry's basename and the AppStream component id to *be* that id —
  so the desktop file, the window's `app_id` and MPRIS's `DesktopEntry` all
  moved from the bare `baz` to the reverse-DNS form together. The MPRIS bus
  name is the spec's, not the desktop's, and stays `org.mpris.MediaPlayer2.baz`.
  Details and the CI check that keeps the five spellings equal:
  `packaging/flatpak/README.md`.
- "Bazaar" adjacency on Flathub is noted and accepted: different word, different category, low confusion risk.

## Consequences

- The name is search-hostile ("baz" is ubiquitous in code examples). Mitigation: consistently brand as "baz music player" in READMEs, package descriptions, and site metadata; the foo→bar→baz homage is the story that makes it memorable.
- Squatting risk until the crates.io reservation happens — do it early in Phase 2.
