# Vibe evaluation harness

This directory answers one question before Baz gains semantic controls: does a
local joint audio/text model make playlists people consistently prefer?

It is deliberately outside the application and Cargo workspace. The harness
has no downloader, never opens Baz's library database, and accepts only an
explicit corpus manifest. Models, private paths, embeddings, ballots and
listening notes belong under ignored `local/`; none should be committed.

## Candidate status

There are three pinned, model-swappable paths:

- `artifacts-laion-reproduced.json` pins Baz's preferred pair, generated by
  `export_laion.py` from every byte in `official-laion.json`: 34.1 MB audio,
  126.6 MB text and 2.1 MB tokenizer. Its text graph carries the required
  attention mask, so padded prompt batches retain the official model's
  semantics. The official checkpoint and model card are Apache-2.0.
- `artifacts-laion.json` retains the independently converted Xenova pair for
  comparison. Its text graph omits `attention_mask`; padded batches materially
  corrupt its embeddings. The evaluator therefore runs that graph one
  naturally sized prompt at a time. Results made with the earlier padded path
  are invalid and must not enter a listening decision.
- `artifacts.json` pins AudioMuse DCLAP v1's original 22.4 MB audio model,
  501.4 MB LAION text export and 2.1 MB tokenizer. AudioMuse's source is
  AGPL-3.0-only and its release gives no separate weight grant, so these are
  **evaluation-only artifacts** pending a full provenance decision.

Do not put an evaluation artifact set into a Baz package or add an
application downloader. The evaluator selects the matching manifest whenever
`--candidate` changes and refuses missing, corrupt or substituted bytes.

## Reproduce the preferred LAION pair

Create a separate export environment; its pinned PyTorch/Transformers stack is
not part of evaluation or Baz's eventual runtime:

```sh
toolbox run -c baz-dev python3 -m venv tools/vibe-eval/local/export-venv
toolbox run -c baz-dev tools/vibe-eval/local/export-venv/bin/pip install \
  -r tools/vibe-eval/requirements-export.txt
```

Obtain official revision
`8fa0f1c6d0433df6e97c127f64b2a1d6c0dcda8a` yourself under
`tools/vibe-eval/local/laion-official/`. The exporter contains no downloader
and verifies all nine files—including the 614,525,833-byte official weight file—before loading
the checkpoint. Export, quantize and compare both towers to PyTorch with:

```sh
toolbox run -c baz-dev tools/vibe-eval/local/export-venv/bin/python \
  tools/vibe-eval/export_laion.py \
  tools/vibe-eval/local/laion-official \
  tools/vibe-eval/local/laion-reproduced
```

`export-report.json` records tool versions, hashes, sizes and cosine checks.
The committed artifact manifest is the result of that exact recipe; generated
models and reports remain ignored.

The evaluator supports the reference policy (every 10-second window with 50%
overlap) and an explicit evenly sampled window cap. A cap is an experiment,
not an optimization assumed to be equivalent: compare its rankings and track
embeddings against the full policy before accepting the speed/quality trade.

## Reproduce

Create a disposable environment in the Toolbox and install the pinned
evaluation dependencies:

```sh
toolbox run -c baz-dev python3 -m venv tools/vibe-eval/local/venv
toolbox run -c baz-dev tools/vibe-eval/local/venv/bin/pip install \
  -r tools/vibe-eval/requirements.txt
```

Download one reviewed artifact set yourself into
`tools/vibe-eval/local/model/`, then prove it contains the pinned bytes. For
the current preferred engineering candidate:

```sh
toolbox run -c baz-dev tools/vibe-eval/local/venv/bin/python \
  tools/vibe-eval/vibe_eval.py verify tools/vibe-eval/local/model \
  --candidate laion \
  --artifacts tools/vibe-eval/artifacts-laion-reproduced.json
```

Omit `--candidate laion` to reproduce the DCLAP comparison instead.

Copy `corpus.example.json` to `local/corpus.json` and list only tracks whose
local analysis you intend. IDs should be stable but anonymous; artist and album
are used only to enforce diversity. Then create both the full reference index
and a sampled challenger:

```sh
toolbox run -c baz-dev tools/vibe-eval/local/venv/bin/python \
  tools/vibe-eval/vibe_eval.py index tools/vibe-eval/local/corpus.json \
  tools/vibe-eval/local/model tools/vibe-eval/local/full.json \
  --candidate laion \
  --artifacts tools/vibe-eval/artifacts-laion-reproduced.json
toolbox run -c baz-dev tools/vibe-eval/local/venv/bin/python \
  tools/vibe-eval/vibe_eval.py index tools/vibe-eval/local/corpus.json \
  tools/vibe-eval/local/model tools/vibe-eval/local/sample-6.json \
  --candidate laion --maximum-windows 6 \
  --artifacts tools/vibe-eval/artifacts-laion-reproduced.json
```

`query` turns an index into a run. The committed request set includes concrete
genre/instrument prompts, subtle affect, negative guidance and two trajectories.
The latter interpolate a text target over the playlist; retrieval remains
separate from sequencing, which also considers continuity and diversity.

```sh
toolbox run -c baz-dev tools/vibe-eval/local/venv/bin/python \
  tools/vibe-eval/vibe_eval.py query tools/vibe-eval/local/full.json \
  tools/vibe-eval/local/model tools/vibe-eval/local/laion.json \
  --candidate laion \
  --artifacts tools/vibe-eval/artifacts-laion-reproduced.json
```

Candidate selection is required for both indexing and querying so that paired
audio/text towers cannot be mixed. Use the DCLAP defaults to create a separate
`dclap.json` run when comparing both semantic candidates.

The intentionally weak metadata control uses only token overlap over the
explicit corpus fields and the same artist/album caps; it never reads audio or
pretends to understand an unmatched mood:

```sh
toolbox run -c baz-dev python3 tools/vibe-eval/vibe_eval.py metadata \
  tools/vibe-eval/local/corpus.json tools/vibe-eval/local/metadata.json
```

The shipped conventional-feature comparator is exported by the workspace
binary. It shares `baz-vibe`'s decoder, cache, tempo/timbre vectors and
diversity policy; its deliberately small adjective map exposes only the two
axes it can substantiate. Arc requests become explicit stepped axis targets,
not claimed semantic understanding:

```sh
toolbox run -c baz-dev cargo run -p baz-vibe --bin vibe-baseline -- \
  tools/vibe-eval/local/corpus.json tools/vibe-eval/requests.json \
  tools/vibe-eval/local/conventional.db tools/vibe-eval/local/conventional.json 20
```

Produce equivalent run JSON from the conventional and metadata controls, then
hide system identity. Keep the key away from the listener until ratings are
finished:

```sh
toolbox run -c baz-dev python3 tools/vibe-eval/vibe_eval.py blind \
  tools/vibe-eval/local/metadata.json tools/vibe-eval/local/conventional.json \
  tools/vibe-eval/local/laion.json tools/vibe-eval/local/dclap.json \
  --ballot tools/vibe-eval/local/ballot.json \
  --key tools/vibe-eval/local/key.json
```

Every run carries the same portable fingerprint over the complete ordered
corpus. `blind` refuses both mismatched IDs and the subtler case where IDs were
reused for different paths or metadata.

Materialize the identity-free rankings as ordinary playlists. They can be
opened by an M3U8-capable player or copied temporarily into Baz's playlists
folder; the command itself does not alter that folder and refuses to replace
an existing listening set:

```sh
toolbox run -c baz-dev python3 tools/vibe-eval/vibe_eval.py materialize \
  tools/vibe-eval/local/ballot.json tools/vibe-eval/local/corpus.json \
  tools/vibe-eval/local/listening
```

Each request directory contains `A.m3u8`, `B.m3u8`, and so on, plus one
identity-free `listening.json` index. The separate key remains the only file
which knows which system produced a letter.

For each candidate list, fill every 1–5 rating and its `preferred` code. Score
only after the ballot is complete:

```sh
toolbox run -c baz-dev python3 tools/vibe-eval/vibe_eval.py score \
  tools/vibe-eval/local/ballot.json tools/vibe-eval/local/key.json \
  tools/vibe-eval/local/score.json
```

The gate remains listener preference. Model cosine, a benchmark claim or one
good-looking list is not sufficient.

Run harness tests without model dependencies:

```sh
toolbox run -c baz-dev python3 -m unittest discover -s tools/vibe-eval -p 'test_*.py'
```
